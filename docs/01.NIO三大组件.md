# 三大组件的介绍
## Channel
它是读取数据的双向通道，既可以写又可以读
我们已经熟悉了Stream，其实Channel 更加底层

## Buffer
这个概念无需多言，最常见的是 ByteBuffer

## Selector
Selector 用来让一个线程管理多个 socket，传统方法是用线程池来管理连接，但是此时一个线程同时只能处理一条连接

更严谨地说，一个Selector 可以监听多个Channel，这些Channel 是**非阻塞**的。Selector 适合**连接多流量低**的场景
流量低可以理解为一个连接交互所需的数据量比较少，（这样每个连接的请求处理的快，使得线程可以顾及多个连接）

# Buffer 详解
## 一个使用Buffer的例子
ByteBuffer.allocate 指定 Buffer 的大小
然后 channel.read() 向 buffer 里写入读取的数据
然后 buffer.flip() 转换成读模式
通过 buffer.get() 一个字节一个字节地读取
buffer.clear() 或者 buffer.compact() 切换回写模式

## Buffer 的常用方法
### 分配
分配需要重点讲一下，因为ByteBuffer依据使用的内存可以分成两种：堆内存和直接内存
* 堆内存读写性能较低（因为额外一次拷贝，说实话我还不是特别理解为什么会有额外一次拷贝），受GC管辖
* 直接内存读写性能高，但是它分配效率低（因为要走系统调用），不受GC约束，自己写代码容易出现内存泄漏
![](/Users/yangli/BackendProject/LearnNetty/docs/graph/Buffer的分配.png)

### 读取
低价值，

buffer.get() 或者 channel.write()

### 重读
低价值，

用 buffer.rewind() 来重设 position，从而实现重复的数据读取

除此之外，还有 mark() 和 reset() 方法， 
mark() 标记 position位置 
reset() 回到 mark 标记的 position 的位置

### 分散读集中写
类似于见过的 readv, writev 系统调用，channel.read() 可以将数据分散读到不同的ByteBuffer里

## 处理流式文本分割
流中的数据分割有3中方案：
* 固定每条消息的长度
* 通过特定的分割符来做分割
* TLV / LTV 格式（type, length ,value)

主流用第三种， http 是第二种和第三种混合式（http头使用分割符来分割，头中有 T 和 L)
