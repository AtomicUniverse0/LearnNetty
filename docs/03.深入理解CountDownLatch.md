# CountDownLatch 初探 
CountDownLatch 的主干结构如下:
```java
public class CountDownLatch {

    private static final class Sync extends AbstractQueuedSynchronizer { /*...*/ }

    private final Sync sync;

    public CountDownLatch(int count) {
        if (count < 0) throw new IllegalArgumentException("count < 0");
        this.sync = new Sync(count);
    }

    public void await() throws InterruptedException {
        sync.acquireSharedInterruptibly(1);
    }

    public void countDown() {
        sync.releaseShared(1);
    }
}
```

其实非常简洁，可以看到它的核心功能都是基于内部的 Sync 实现的，那么我们单独看看 Sync 的内容
在读的时候，会注意到内部一直有 setState 和 getState() 的调用，它其实是在读取和写入父类的一个
volatile 的整数:
```java
public abstract class AbstractQueuedSynchronizer{
    private volatile int state;

    protected final int getState() {
        return state;
    }

    protected final void setState(int newState) {
        state = newState;
    }
}
```

好了，正式来读一下：
```java
private static final class Sync extends AbstractQueuedSynchronizer {
    private static final long serialVersionUID = 4982264981922014374L;

    Sync(int count) {
        setState(count);
    }

    int getCount() {
        return getState();
    }

    // 不使用传入的参数，如果 state 为0 则返回1， 否则返回-1
    protected int tryAcquireShared(int acquires) {
        return (getState() == 0) ? 1 : -1;
    }

    // 也不使用传入的参数，用CAS来将 state 减 1
    // 如果发现在执行减法之前， state 已经是0了，那么返回false
    // 如果执行减法之后，state 不是0， 也返回 false
    // 如果执行减法之后，state 为0， 则返回 true
    protected boolean tryReleaseShared(int releases) {
        // Decrement count; signal when transition to zero
        for (;;) {
            int c = getState();
            if (c == 0)
                return false;
            int nextc = c - 1;
            if (compareAndSetState(c, nextc))
                return nextc == 0;
        }
    }
}
```
Sync 的成员方法真的只有这4个，看来 `acquireSharedInterruptibly` 和 `releaseShared` 都是 AQS自己实现的。

# AQS 详解
那么我们就来看一下 AQS 的方法，AQS的源码有2000多行，我们不可能一口气读完，我们
只需揣着如下两个问题来逐步抽死剥开茧即可：
1. `acquireSharedInterruptibly` 是如何实现的？
2. `releaseShared` 是如何实现的？

首先来看与上述两个方法直接相关的代码:
```java
public abstract class AbstractQueuedSynchronizer
    extends AbstractOwnableSynchronizer
    implements java.io.Serializable {

    // 空的构造函数
    protected AbstractQueuedSynchronizer() { }

    abstract static class Node {/*...*/}

    private transient volatile Node head;

    private transient volatile Node tail;
    
    // 这两个方法是 AQS 共享模式下的获取入口和释放入口

    // 尝试获取，获取不到时进入等待，等待过程中可以响应中断
    public final void acquireSharedInterruptibly(int arg)
        throws InterruptedException {
        if (Thread.interrupted() ||
            (tryAcquireShared(arg) < 0 &&
             acquire(null, arg, true, true, false, 0L) < 0))
            throw new InterruptedException();
    }

    // 执行共享释放，并在状态变化可能让等待线程获取成功时，通知后继线程继续尝试
    public final boolean releaseShared(int arg) {
        if (tryReleaseShared(arg)) {
            signalNext(head);
            return true;
        }
        return false;
    }

    private static final Unsafe U = Unsafe.getUnsafe(); // 这个类会在 Node 里被用到
}
```
在上面的代码片段中，我先简单标记了两个关键函数的功能，在深入研究它们的功能之前，我们发现有两个陌生

## AbstractOwnableSynchronizer(AOS)
AQS 是 AOS 的子类，因此有必要了解一下AOS，它作用很简单：记录当前由哪个线程独占这个同步器。
AQS 继承它，就获得了记录独占持有者的能力，它的源码很简单，单纯就是维护一个Thread引用。

## Node
### Node 详解
AQS是通过链表来排队的，而 Node 是链表的核心元素，我们来看一下它
```java
    /* CLH 是 Craig、Landin、Hagersten 三位研究者姓氏的首字母，指一种基于队列的锁算法 */
    
    /** CLH Nodes */
    abstract static class Node {
        volatile Node prev;       // initially attached via casTail
        volatile Node next;       // visibly nonnull when signallable
        Thread waiter;            // visibly nonnull when enqueued
        volatile int status;      // written by owner, atomic bit ops by others

        // methods for atomic operations
        
        // cas进行原子替换，this.prev 原本是 c，将它改为 v 
        final boolean casPrev(Node c, Node v) {  // for cleanQueue
            return U.weakCompareAndSetReference(this, PREV, c, v);
        }
        final boolean casNext(Node c, Node v) {  // for cleanQueue
            return U.weakCompareAndSetReference(this, NEXT, c, v);
        }
        // 原子地读取 node 的 status，并把值设为0
        final int getAndUnsetStatus(int v) {     // for signalling
            return U.getAndBitwiseAndInt(this, STATUS, ~v);
        }
        
        // 不做 cas，单出将引用p写入 this.prev
        final void setPrevRelaxed(Node p) {      // for off-queue assignment
            U.putReference(this, PREV, p);
        }
        // 直接将 s 写入 this.status
        final void setStatusRelaxed(int s) {     // for off-queue assignment
            U.putInt(this, STATUS, s);
        }
        // 直接将 status 清零
        final void clearStatus() {               // for reducing unneeded signals
            U.putIntOpaque(this, STATUS, 0);
        }

        // 获得几个字段相对于对象指针的偏移
        private static final long STATUS
            = U.objectFieldOffset(Node.class, "status");
        private static final long NEXT
            = U.objectFieldOffset(Node.class, "next");
        private static final long PREV
            = U.objectFieldOffset(Node.class, "prev");
    }
```
可以看到，Node基于 Unsafe 提供了一些原子/非原子的对自身变量进行修改的方法，上述方法中，比较有意思的是
setPrevRelaxed 和 setStatusRelaxed 这两个方法。 
以前者为例，setPrevRelaxed 和 this.prev = p 有何不同？
答案是：prev 被声明为 volatile，但 setPrevRelaxed(p) 使用普通写入语义； 直接写 this.p 则是 volatile 语义

### Node 的实例
另外，细心的读者可能发现了，Node是一个抽象类，它无法实例化，实际上AQS内部提供了3个Node的实例类:
```java
    static final class ExclusiveNode extends Node { }
    static final class SharedNode extends Node { }

    static final class ConditionNode extends Node
        implements ForkJoinPool.ManagedBlocker {
        ConditionNode nextWaiter;            // link to next waiting node

        /**
         * Allows Conditions to be used in ForkJoinPools without
         * risking fixed pool exhaustion. This is usable only for
         * untimed Condition waits, not timed versions.
         */
        public final boolean isReleasable() {
            return status <= 1 || Thread.currentThread().isInterrupted();
        }

        public final boolean block() {
            // LockSupport.park() 底层会通过 Unsafe 类的native 方法来让进程进入阻塞状态
            // 如果 unpark() 先于 park() 调用，则 unpark 的目标线程会收到一个许可，等这个
            // 线程调用 park() 时，就消耗这个许可，从而避免进入沉睡
            
            // linux 的 wakeup() 和 sleep() 也有这种允许 wakeup 稍微早于 sleep 的机制，
            // 但不能任务 wakeup 分配了一个许可
            while (!isReleasable()) LockSupport.park();
            return true;
        }
    }
```

ExclusiveNode 和 SharedNode 实际上就是Node本身，只是名字不同。而ConditionNode则需要好好讲解一下。

首先，它实现的接口,ManagedBlocker, 把“是否需要阻塞”和“如何阻塞”交给实现类，
让线程池有机会在工作线程阻塞前进行补偿。

两个方法如下:
```java
    public static interface ManagedBlocker {
        // 必要时实际阻塞当前线程，true：无需继续阻塞；false：还需要继续检查、等待
        boolean block() throws InterruptedException;

        // 不阻塞地检查是否还需要等待，返回 true：无需阻塞；false：仍需阻塞

    }
```

## acquireSharedInterruptibly 详解
代码非常简短：重点在于 tryAcquireShared 和 acquire 这两个成员方法
```java

    extends AbstractOwnableSynchronizer
    implements java.io.Serializable {

    public final void acquireSharedInterruptibly(int arg)
            throws InterruptedException {
        if (Thread.interrupted() ||
                (tryAcquireShared(arg) < 0 &&
                        acquire(null, arg, true, true, false, 0L) < 0))
            throw new InterruptedException();
    }
}
```
### tryAcquireShared
AQS自身没有实现 tryAcquireShared, 这里调用的是 Sync 的，tryAcquireShared
```java
    protected int tryAcquireShared(int acquires) {
        return (getState() == 0) ? 1 : -1;
    }
```
可见，如果 state != 0，则 tryAcquireShared 返回 -1， 此时 tryAcquireShared(arg) < 0 就成立
因此与运算会执行后续的 acquire（）

否则，当 state == 0， tryAcquireShared(arg) < 0 为 false， 不会执行后续的 acquire

由此可见， tryAcquireShared 发挥的作用，类似于“先提前看一眼是否有可能 acquire”

### acquire
这个 acquire 就是个硬骨头了，在读之前，需要着重介绍 acquire的第一个参数 Node。

node 表示“当前线程用于排队获取资源的节点”。 这个参数主要是为了让同一套获取逻辑同时支持普通获取，以及 Condition.await() 结束等待后重新获取锁
* 普通获取通常传 null。 此时线程还没有等待节点
* 条件等待后的重新获取，会传入已有的ConditionNode
如果你没太看懂也没关系，先记住"在CountDownLatch 的 await() 方法底层调用 acquire 时 node 为 null" 即可 

总之，先往下看吧
```java

    final int acquire(
        Node node,  // null
        int arg,    // arg
        boolean shared, // true
        boolean interruptible, // true
        boolean timed,  // false
        long time      // 0
    ) {
        Thread current = Thread.currentThread();
        byte spins = 0, postSpins = 0;   // retries upon unpark of first thread
        boolean interrupted = false, first = false;
        Node pred = null;                // predecessor of node when enqueued

        for (;;) {
            /* 
                1. 当 node 为 null 时， pred 为 null， 否则为 node.prev
                所以这里的 pred != null 条件不满足，该分支不会被触发
             */
            /*
                6. 第二轮回到这里时， node 不为 null 了，可 node.prev 是 null
                因此 pred 仍是 null，这里的 pred != null 不满足，该分支仍然不触发 
            */
            /*
                12. 第三轮回来， node.prev 仍然是 null。。。这个分支仍然不触发
             */
            /*
                17. 第四轮回来，node.prev 终于不是 null了，而是一个 dummyNode，然而此时 head 也是 dummyNode，因此 head == pred 为 true
                    所以 first = (head == pred) 中的 first 为 ture， 这意味这个 node 是链表中的第一个节点，此分支仍然不触发
             */
            /*
                22. 第五轮回来，结论和第四轮一样
             */
            if (!first && (pred = (node == null) ? null : node.prev) != null &&
                !(first = (head == pred))) {
                if (pred.status < 0) {
                    cleanQueue();           // predecessor cancelled
                    continue;
                } else if (pred.prev == null) {
                    Thread.onSpinWait();    // ensure serialization
                    continue;
                }
            }
            
            /* 2. pred 为 null，这段分支会被触发 */
            /* 7. 第二轮到这里，pred 仍然为 null, 仍触发这个分支*/
            /* 13. 第三轮来这，仍然触发这个分支，内部会进行 acquire 的判断*/
            /* 18. 第四轮来到这里，first 为 true, pred 为 dummyNode，这个分支仍然被触发*/
            /* 23. 第五轮来，仍然一样。。。*/
            if (first || pred == null) {
                boolean acquired;
                try {
                    /* 
                        3.shared 为 true，因此会调用 tryAcquireShared 而非 tryAcquire
                        回忆一下，当 state != 0 是，tryAcquireShared 返回 -1， 因此 acquired = false
                        否则，acquired = true
                    */
                    /*
                        8. 第二轮回到这里，执行结论仍然和3.一样
                     * */
                    if (shared)
                        acquired = (tryAcquireShared(arg) >= 0);
                    else
                        acquired = tryAcquire(arg);
                } catch (Throwable ex) {
                    // 几乎可以认为 tryAcquireShared 不抛出异常，这个分支就不看了
                    cancelAcquire(node, interrupted, false);
                    throw ex;
                }
                    /*
                        4. 如果 acquired 为 true，则直接返回 -1
                    */
                    /*
                        9. 第二轮回到这里，如果在创建 SharedNode 之后，acquried 变为 true了，则直接返回
                    */
                    /*
                        14. 第三轮回这里，结论仍和 第一，第二轮一样。。。
                     */
                    /*
                            19，第四轮来到这里，结论仍和 ... 一样..
                     */
                if (acquired) { 
                    if (first) {
                        /**
                         * first = true 意味着这个节点已经进入了队列，并且是第一个节点
                         */
                        node.prev = null;
                        head = node; 
                        // head 设为 node 了，那么下一个有权获取锁的就是 node.next 了吧
                        // 这与第一个分支里的 (first = (head == pred)) 相呼应，通过 head == node.prev来判断 node 是否有权获取锁
                        pred.next = null;
                        node.waiter = null;
                        if (shared)
                            signalNextIfShared(node);
                        if (interrupted)
                            current.interrupt();
                    }
                    return 1;
                }
            }
            
            /* 
                5. 运行到这里，说明 acquired = false, 即 stated != 0
                此时 node 确实是 null，并且 shared 为 true 因此会导致 node = new SharedNode()
                并且，剩下的一堆 else if 就不会被执行了，直接返回 for( ;;) 的开头
            */
            /*
                10. 第二轮回到这里， node 不为 null 了，可是 pred 为 null 所以进入第二个 else if 分支
             * */
            /*
                15. 第三轮回到这里，node 不为 null 了，可是 pred 仍然是 null， 仍进入第二个 else if 分支
             */
            /*
                20. 第四轮来到这里，node 不为 null， pred 为 dummyHead, 也不为 null， 所以第一，第二个分支不会触发
                    由于 spins 为 0， 因此第三个分支也不触发
                    node.status 确实为 0，因此会触发第四个分支，将 status 设为 waiting
             */
            /*
                24，第五轮回来，直接进入最后的那个 else 分支
             */
            if (node == null) { 
                if (shared) 
                    node = new SharedNode();
                else
                    node = new ExclusiveNode();
            } else if (pred == null) {          // try to enqueue
                /* 
                    11. 第二轮回到这里，进行入队操作。 t == null，因此 tryInitializeHead()的分支会被触发，
                    tryInitializeHead 内部会新建一个 dummyNode，将 this.head 和 this.tail 设定为这个 dummyNode
                    
                    当第二轮执行完之后， 
                        node.waiter 指向当前线程， 
                        node.prev 为 null ，
                        tail 和 head 为 dummyNode
                    
                    该回到第三轮了
                */ 
                
                /*
                    16. 第三轮来到这里， tail 为 dummyNode，因此 node.prev 会被设置为 dummyNode
                        然后会执行 casTail(t, node)，它会将 当前这个 AQS 的 tail 字段从 node.prev 改为 node
                        
                        如果cas 失败，则将 node.prev 设为 null重新回到循环一开始，重新开始循环，直到 acquire 成功，函数退出，
                        或者 cas 成功，此节点正式加入链表
                 */
                node.waiter = current;
                Node t = tail;
                node.setPrevRelaxed(t);         // avoid unnecessary fence
                if (t == null)
                    tryInitializeHead();
                else if (!casTail(t, node))
                    node.setPrevRelaxed(null);  // back out
                else
                    t.next = node;
            } else if (first && spins != 0) {
                --spins;                        // reduce unfairness on rewaits
                Thread.onSpinWait();
            } else if (node.status == 0) {
                /*
                    21. 第四轮会来到这里，执行 node.status = Waiting，然后进入第五轮
                 */
                node.status = WAITING;          // enable signal and recheck
            } else {
                /*
                   25. 第五轮回来，会执行这个，注意这是唯一一个会执行 break 的分支，因此这个分支的内容是唯一会导致 cancelAcquire 的。
                   有两点需要注意，
                   第一个是，注意这里会对 spins 和 postSpins 进行更新，它们是用来实现自旋额度的：线程被唤醒后，会有几次自旋的机会，防止立刻进入 park
                   第二个是，这里的 break 条件： 当获取锁的时间超过，或者醒来时发现线程被中断后，才会执行 break，从而执行cancelAcquire。
                 */
                long nanos;
                spins = postSpins = (byte)((postSpins << 1) | 1);
                if (!timed)
                    LockSupport.park(this);
                else if ((nanos = time - System.nanoTime()) > 0L)
                    LockSupport.parkNanos(this, nanos);
                else
                    break;
                node.clearStatus();
                if ((interrupted |= Thread.interrupted()) && interruptible)
                    break;
            }
        }
        return cancelAcquire(node, interrupted, interruptible);
    }
```

读完了顿觉被榨干了，acquire 内部其实是一个将各项操作中间安排上 acquire 检查的循环:
假设在没有竞争的情况下，一个 CoundDownLatch 底层 await 所调用的 acquire 的流程如下:
acquire() 被调用 -> 检查 tryAcquireShared() 是否成功 -> 新建 Node -> 检查 tryAcquireShared ...
-> 初始化链表的头和尾为一个 dummyNode -> 检查... -> 将 Node 插入节点 -> 检查 ...
-> 设置 Node 的 status 字段 -> 检查... -> 进入睡眠 -> 醒来后检查。。。

一个值得注意的细节是， head.next 才是当前有权做 acquire 的 node，而非 head 本身
并且 node 的插入方式是尾插法，tail 指向新加入的 node

### cancelAcquire
在线程被打断，或者锁等待超时的情况下，acquire 会执行 cancelAcquire，我们看一下实现方式:
在我们的场景下，Node 肯定不为 null， node.prev 也不为 null， 
所以cancelAcquire 的执行流程如下:

将 node.waiter 晴空，将 node.status 设为被取消，调用 cleanQueue，
然后，如果被中断，且该锁是可中断的，则返回负数，否则，将当前线程设为中断，然后返回0
```java

// 被中断，返回负数或者抛异常
// 如果是正常超时，则返回 0
    private int cancelAcquire(Node node, boolean interrupted,
                              boolean interruptible) {
        if (node != null) {
            node.waiter = null;
            node.status = CANCELLED; // CANCELLED 是一个负数!
            if (node.prev != null)
                cleanQueue();
        }
        if (interrupted) {
            if (interruptible)
                return CANCELLED;
            else
                Thread.currentThread().interrupt();
        }
        return 0;
    }
```

我们还需要看一下 cleanQueue()， 该方法内部调用了 signalNext 这个方法，它的作用是唤醒h.next，并且调用者需要确保 s.status 不是 Cancel
```java
    private static void signalNext(Node h) {
        Node s;
        if (h != null && (s = h.next) != null && s.status != 0) {
            s.getAndUnsetStatus(WAITING);
            LockSupport.unpark(s.waiter);
        }
    }
```

```java
    private void cleanQueue() {
        for (;;) {                               // restart point
            // q 是当前，p 是前驱，s 是后继
            for (Node q = tail, s = null, p, n;;) { // (p, q, s) triples
                // 队列中没有待释放的节点了，可以结束了
                if (q == null || (p = q.prev) == null)
                    return;                      // end of list
                
                // 当此时插入了新的 node 时，终结此轮遍历，重新开始遍历
                if (s == null ? tail != q : (s.prev != q || s.status < 0))
                    break;                       // inconsistent
                
                // 当前节点被取消，则需要将这个节点从队列中摘除，具体的操作如下:
                // 如果没有后继，则通过 cas 将当前的 tail 变为当前节点的前驱
                // 如果有后继，则让后继通过 cas 将它的前驱变为 当前节点的前驱
                if (q.status < 0) {              // cancelled
                    if ((s == null ? casTail(q, p) : s.casPrev(q, p)) &&
                        q.prev == p) {
                        p.casNext(q, s);         // OK if fails
                        
                        // 重点，这里的 p.prev == null 意味着，当前这个被移除的节点，正是队列中目前有权进行 acquire 的节点
                        // 那么，当前这个节点被移除了就该唤醒后面的节点，让它来 acquire 了
                        if (p.prev == null) 
                            signalNext(p);
                    }
                    break;
                }
                
                // 这是一种边界情况，p - n - q 的情况， n 是一个正在被摘除的节点，它执行了 14 行前的s.casPrev()， 使得 q.prev 为 p
                // 但此时 p 还没执行 casNext(n,q)，因此 n 还挂在 p.next 上
                // 对于这种场景，选择帮助对方完成?
                if ((n = p.next) != q) {         // help finish
                    if (n != null && q.prev == p) {
                        p.casNext(n, q);
                        if (p.prev == null)
                            signalNext(p);
                    }
                    break;
                }
                s = q;
                q = q.prev;
            }
        }
    }
```
读完之后，可以学到的事，cleanQueue 从尾部开始遍历，并发安全地删除链表中所有 status 为 Cancel的节点

## releaseShared
前面我们读完了acquireSharedInterruptibly， 那么接下来就要读取releaseShared了
```java
    public final boolean releaseShared(int arg) {
        if (tryReleaseShared(arg)) {
            signalNext(head);
            return true;
        }
        return false;
    }
```

signalNext我们已经读过了，接下来重要的就是读取 tryReleaseShared 了
```java
    // 也不使用传入的参数，用CAS来将 state 减 1
    // 如果发现在执行减法之前， state 已经是0了，那么返回false
    // 如果执行减法之后，state 不是0， 也返回 false
    // 如果执行减法之后，state 为0， 则返回 true
    protected boolean tryReleaseShared(int releases) {
        // Decrement count; signal when transition to zero
        for (;;) {
            int c = getState();
            if (c == 0)
                return false;
            int nextc = c - 1;
            if (compareAndSetState(c, nextc))
                return nextc == 0;
        }
    }
```
而 tryReleaseShared 非常简单，我们已经读过了，它用 cas 对 state 减一，减到0就返回true，否则返回false
